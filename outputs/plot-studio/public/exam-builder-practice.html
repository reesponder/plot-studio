Create the three pages.

Task instructions

Use Home (index), Services (services) and Contact (contact). Add one meaningful H1 or hero heading per page. Give each page a navigation menu that reaches the other two. Add a named Home button or hero action that leads directly to Contact.

How I solve it

  1. Set the page names and routes

    I keep the existing Home page as the index and create Services with slug services and Contact with slug contact in Design → Pages.

  2. Give every page a distinct heading

    I use “Rooms with a point of view.” on Home, “Services” on Services, and “Contact” on Contact. I check each H1 on the canvas.

  3. Build the navigation and Home action

    I add a Navigation block to all three pages. With automatic page links enabled, I confirm each menu reaches both other pages. I set the Home hero action to “Start an enquiry” and choose Contact as its destination.

  4. Check the links in Preview

    Starting from Home, I open Contact with the new button. I return via Services and Home using the navigation, then repeat using Phone Preview.

How I check it

Home action
“Start an enquiry” opens Contact directly, with the Contact heading visible.
All three menus
Home reaches Services and Contact. Services reaches Home and Contact. Contact reaches Home and Services.
Desktop and Phone
The same navigation works on both sizes. At each stop I can identify the new page from its heading.

Wire the live result.

Task instructions

Connect the Contact form’s Form submission event to a Set text node. Target a visible text element in Contact and enter a meaningful, literal confirmation message. Prevent the native form submission so the page can display the result. Use Blueprint nodes for the behaviour.

How I solve it

  1. Make the confirmation visible

    I add a paragraph immediately below the Contact form. I label it “Contact status” in the editor so that I can pick the right target, and give it the starting text “Use the form above to send your enquiry.”

  2. Select the correct trigger

    In Logic I add Form submission and choose the form on Contact as the target. I enable the option to prevent the native submission. That keeps Contact open after the event.

  3. Set the exact message in the graph

    I connect the trigger’s execution output to Set text, select Contact status and type “Thank you. Your enquiry was received.” as the action’s literal text. I leave the value input unwired so all valid submissions get the same message.

  4. Run both cases in Preview

    I submit once with Message empty, then provide Riley Sample, riley@example.com and “Please send your opening hours.” I check both behaviours in Desktop and Phone Preview.

How I check it

Required Message left blank
The browser highlights Message and the original text stays in place.
Valid submit
The paragraph reads “Thank you. Your enquiry was received.” and the Contact page stays open.
Fresh Preview at Phone width
The original paragraph appears when I open the page. Submitting again updates that same visible paragraph.
