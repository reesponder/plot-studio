Start a project

Use Open Studio in the header and sign in with the password you received. If you need access, get a Studio licence. The editor opens the active draft for the current browser. Use the menu beside the PLOT logo to rename, create, import, or open a different project.

  1. Open the project menu and choose New blank project if you are building a separate site. Use Download .plot project first if you want a checkpoint of the current work.
  2. Choose Rename project and give the new site a name you will recognize in the browser and on the server.
  3. Open Design, then Pages. List the pages visitors will need and decide where each primary button should take them.
  4. Make one working page before styling the entire site. Add a heading, a paragraph, and one button, then verify the page in Preview.

The editor views have different jobs. In Design, arrange page blocks and edit their content and appearance. In Logic, connect triggers and actions. In Data, define fields, add records, and decide which operations visitors may call. In Backend, build and test server workflows and publish a private site. In Code, inspect the generated site files and optionally add site-wide CSS or JavaScript. The built-in blocks and nodes are enough to complete the standard recipes in this guide.

To learn from a finished layout, choose Open Lindenbank House demo. The project includes a hotel home page, rooms, dining, a local guide and a booking enquiry. To inspect a graph that writes records, choose Open form + database demo. Both commands ask before replacing the active draft.

Set up your first work session

Decide whether you're beginning a new site or revising an existing one. If you are revising, download a .plot checkpoint before changing anything and name it with the date. Use Import project in the project menu to resume from a checkpoint. Use a separate draft for practice.

Build one working page first. Add a heading, a paragraph and a button, then test the button in Desktop and Phone Preview. In the hotel demo, find a room photo in the canvas, Layers and the inspector. Drag either panel divider to resize it, double-click a divider to reset it, or use Canvas only to make space temporarily. Use Canvas zoom in the bottom bar to return to Fit or inspect a larger view.

Pages and navigation

Choose Pages in the Design library and select Add page. Enter the page name and check the URL slug. Start with a blank page or select a Product landing page, Portfolio, Documentation, or Contact template. Templates give you editable blocks and placeholder content. Replace every example heading, link, email address, and form instruction before exporting.

The home page exports as index.html. A page with the slug services exports as services.html. Keep slugs short and unique. Changing a slug after you distribute the site changes its exported filename. Update any manually entered links to the old path and any external links under your control.

Make routes easy to test

Add a Navigation block near the top of the page. Its Content tab includes a brand name, links, and an optional button. Turn on Add pages automatically to include project pages in menus that should follow the page list. Use the manual list when you want a specific order, an external destination, or shorter menu labels. Each line uses a label and URL separated by a vertical bar.

Home | index.html
Services | services.html
Contact | contact.html

For a link within the same page, select the destination section or heading and set its Anchor ID to a simple value such as pricing. Enter #pricing in the button or link URL field. Add a Footer for links people may look for after reading. In Preview, follow the same routes a visitor would take, including your return path to Home.

Use normal links for navigation. A button that changes something on the current page can keep the default # destination and use a Click node. Give it a label that describes the action, such as “Show pricing details” or “Copy reference number.”

Check routes from both directions

Make a short route list with the menu label, its destination and a second way to reach each important page. Start with Home, a useful internal page and a Contact path. Add anchors after sections have stable names. The Studio page name identifies the destination in the editor. Its slug determines the exported filename.

Studio's page links can refer to the destination's identity internally. Check every URL typed by hand after changing a slug. In Preview, follow each destination from Home, confirm the page title, and return to Home using the site's own menu. Test footer links and in-page jumps separately. If a page came from a template, check its example links and form fields before the first export.

Design with blocks

For complete layouts, styling walkthroughs and editable project downloads, open the Design handbook.

In Design you can pick built-in element variants, move and resize blocks on the canvas, and place photos from The Stock of Freedom.

Open Elements in the Design library. Click an element to add it or drag it onto the canvas. Use Section to group a region of the page and Columns for content that belongs side by side. Use Layers to see the hierarchy. A block nested inside a container moves with that container. Shift-drag a block into a supported container when you want it to become a child.

Click a block on the canvas or choose it in Layers to inspect it. Double-click supported rendered text to edit it on the canvas. Use Content to change a block's written copy, labels, links, and other settings. Use Style for layout, dimensions, spacing, colors, typography, borders, and shadow. The available Content controls depend on the type of block.

  • Hero, Heading, Text, Link, Button. Use a single clear opening heading. Give later sections heading levels in reading order. Write button labels that describe the destination or action.
  • Feature, Card, Quote, FAQ, Table, Callout. Match the block to what the reader needs. A FAQ suits short questions, while a Table makes rows with the same attributes easier to compare.
  • Form, Input, Select, Toggle. A Form can show preset fields and contain child controls. Give controls stable field names before connecting them to logic or data.
  • Image, Gallery, Video, Audio. Use direct media URLs, meaningful text alternatives, and captions where they help readers understand the material.

Use Site themes in the project menu to set a coordinated baseline. For a specific block, adjust its width, padding, or type only when the design calls for a local variation. A width of 100% lets a block follow its container. A max width can keep reading text comfortable on wider screens. Padding controls space inside the block, while margin controls distance from neighboring content.

When an edit lands in the wrong place, use Undo in the Design toolbar. Before larger changes, download a project file. A known working copy makes it easy to compare which change affected the page.

Work from structure to appearance

Inspect the parent and child relationship before changing a block's width. A card at 100% fills its cell, while Columns determines the space each cell receives. Move a section to change page order. Select one child when the change only belongs to that block.

Check Content first. A heading's tag establishes its place in the page outline. Its font, size and weight live in Style. Give each page a clear top heading and use a consistent level for peer sections. Pick a site theme early, then test the chosen fonts with real headings and the longest paragraph in the project copy. Expand one Style group at a time when diagnosing layout, spacing or type.

Responsive layouts

Use Desktop, Tablet, and Phone in Design to work at different widths. Start by getting the order and content of the page right. Then set overrides for layout changes that are specific to smaller screens. The inspector distinguishes inherited values and local changes. A phone override is useful for stacking content, reducing a large heading, or changing spacing on a crowded call to action.

  1. Check Desktop first. Review the overall hierarchy, the width of long paragraphs, and the placement of the primary action.
  2. Check Tablet. Look for a navigation label breaking onto a second line, a narrow sidebar, or a three-column section that needs more room.
  3. Check Phone. Verify that body text can be read without zoom, buttons fit ordinary labels, and the page can be navigated by touch.
  4. Open the interactive Preview at the same widths. Test the navigation, menu, form controls, and logic with real clicks and keyboard actions.

Fix an overflowing item at its source. Check the child width and minimum width, then inspect its parent's layout, wrap, or column settings. Reduce unnecessary fixed dimensions before hiding the overflowing area. If an image crop cuts off important content, adjust its fit or change the aspect ratio. Test a long label and a realistic paragraph, because placeholder content often hides wrapping problems.

Make one deliberate breakpoint change

Select a heading inside a narrow column and note its desktop font size. Switch to Phone and reduce the size until the full heading fits. Return to Desktop to confirm the base value. A Phone style can also inherit a Tablet override, so change one device at a time when diagnosing a mismatch. Use Clear overrides on the selected block and device to restore inherited values.

If several children collide, inspect the containing column group. It may need fewer columns, a smaller gap or room to wrap. Account for the space padding takes inside the container. Recheck the actual Phone Preview with long labels, images and populated form fields, then test the keyboard order and touch targets.

Upload and use image assets

Upload an image in Studio to get a direct address you can use in a project or share. From the Assets library you can also place the image on a page, fill an existing image field or open a copy in Paint.

Place a saved image Use an external URL Draw in Paint Save a drawing

Upload images to Studio

  1. Open Assets in the Studio toolbar. On a phone, look for the picture icon. Choose Upload images or drop files into the library.
  2. Select files with a supported extension. Studio accepts .png, .jpg, .jpeg and .webp up to 12 MB and 16 megapixels each, with a maximum of 8192 pixels on either side.
  3. Select the thumbnail. The detail panel shows the name, dimensions and Public image URL. Select Copy link to reuse the address in another block, project or site.
  4. Open the link in a private browser window. Anyone with the URL can view the image. Keep files that should stay private in your local drawing workspace.

Studio checks the actual image type and removes embedded metadata. Renaming an SVG or a damaged file to .png will still produce an upload error. If you reach a limit, resize the image or export a smaller copy before uploading again.

Add an image or fill an existing field

Open the page you want to change in Design. Use Assets → Use on page to add an Image block. To replace an existing picture, select its block, open the Content tab, and choose Choose from assets. Select the asset and use Apply to field. A Gallery gets a new entry. An individual image field takes the selected URL.

Select Edit in Paint in the library to open a copy on a new sheet. Save the result to get a new URL. To update a block that still uses the original image, apply the new asset to that field. Other pages can keep using the original address.

Use an external file URL

Images in Image, Hero, Card and Gallery blocks and video posters also accept direct HTTP or HTTPS addresses. External files continue to be served by their original hosts when someone visits your published or exported site.

  1. Open the image on the source site and copy its actual image address. A sharing page, a search results page, and the URL from a private dashboard often point to HTML rather than the image file.
  2. Open the copied address in a fresh browser tab. If access depends on your account, test it in a private window that has no active session for that host.
  3. Open the block's Content tab and paste the full address into the image field. Use HTTPS for an HTTPS site so the browser can load it securely.
  4. Add concise alt text for an image with information. Describe the part that matters to the reader. Put credits, dates, and extra context in the caption where useful.
  5. Verify the image in Preview at Desktop and Phone widths. If the file disappears, test the exact address again. Some hosts expire links or restrict use from other websites.

Gallery entries use one image per line. Put the direct image URL first, then optional alt text and a caption separated by vertical bars. The addresses below are placeholders. Replace each one with a real URL before testing.

https://images.example.com/lobby.webp | Lobby with oak benches | Main entrance
https://images.example.com/stair.webp | Daylight on a brick stair | Stair detail

Prefer stable addresses over temporary signed links. The ZIP preserves remote image references, so the same host must serve them after launch. For an image that changes in response to a visitor's choice, give the Image block a working default URL first, connect the behavior in Logic, and verify both sources separately.

Replace and verify media

Choose the block that matches the content. A Hero image frames the opening, an Image block can carry an individual caption, and a Gallery groups related images. Write alternatives that explain what readers would miss if the image were skipped. Leave decorative alternatives empty when the surrounding words already explain the subject.

Keep the original working address before replacing an image. Paste the replacement, tab away and check the rendered crop. Check each gallery caption after reordering the lines. If the image stays empty, open the exact URL privately to see whether it requires a login, has expired, or depends on a site that prevents embedding. A well-formed gallery line still needs a host that serves its image.

Draw and edit in Paint

Open Paint from the Studio toolbar. The drawing surface sits between the tools and their settings on desktop. On a phone, swipe the tool row to see more tools and open Tool settings below the canvas. Select Open image to start with a local file, or choose Edit in Paint on an asset.

Drawing sheets Pixel sizing and selection Remove a background Export and upload

Work with brushes, shapes and text

Set a primary and secondary color in Tool settings. Use Swap to exchange them. Pick Pencil for crisp marks, or Brush for a wider stroke. Width sets the number of pixels across the stroke. Opacity controls how much color you apply. Try round, flat, marker, watercolor or pixel tips on a spare sheet. Enable Pen pressure if your stylus provides pressure input.

Drag a rectangle, ellipse or another shape on the canvas. Set its outline and fill before placing it. To add a label, select Text, enter the words in Tool settings, set the font and pixel size, then click on the canvas. Paint places the text as pixels, so use Undo and place it again if you want to change the wording. Use Eyedropper to sample colors, Fill to color a connected area and Eraser to clear pixels.

Keep alternatives on drawing sheets

Select Add sheet next to the tabs, name the sheet and enter its width and height. Choose a transparent, white or primary-color background. To compare two versions, choose Sheet actions → Duplicate sheet before editing. Rename each version for its purpose, such as Header badge and Dark background badge. You can keep up to 24 sheets, subject to the total pixel limit.

Paint saves its sheets in this browser. Download a sheet or the entire set to keep a copy on another device. Deleting a local sheet removes the drawing and its history from Paint. Images already saved to Assets keep their URLs.

Edit pixels, resize and crop

  1. For a small icon, make a sheet at the target size, such as 32 × 32 pixels. Increase the zoom percentage and turn on Pixel grid. A 1 px pencil helps you correct individual pixels.
  2. Choose Select and drag around the part you need. Move the selection or choose Crop selection to keep only that area. Use Copy or Cut in Selection & clipboard to reuse a patch.
  3. In Image → Resize, enter the target dimensions. Turn off Keep aspect ratio if the width and height need to change independently. Choose Scale using nearest neighbor for hard pixel edges, Scale image to fit for smooth illustration or photography, or Change canvas only to adjust the available space without resampling the drawing.
  4. Choose Fit to bring the whole drawing into view. Check the finished asset at its intended size on the page.

Remove a solid or simple gradient background

  1. Open the image and duplicate its sheet so you can compare the result with the original.
  2. In Image → Remove background, start with the default tolerance. Studio samples the corners and clears matching pixels connected to the edge.
  3. Look for the transparency checkerboard. If the border has a fringe, undo and try a little more tolerance. If part of the subject disappears, undo and lower it. Use Include matching pixels inside the drawing only when those interior areas should also become transparent.
  4. Check the silhouette against a light and a dark page background. Busy photographs and subjects that touch the edge or share the background color can need manual cleanup. Export as PNG or WebP to keep transparency.

Export a drawing or save it as an asset

Choose Export inside Paint to download a file. Use PNG for crisp edges and transparency, WebP when you want a smaller image that can retain transparency, or JPEG for a flattened image. For JPEG, select a background color for the transparent areas. Select All sheets · PNG ZIP to download every sheet together.

To trace an image, open Reference at the top of Paint and choose a PNG, JPEG or WebP from your device or Assets. Set the opacity and layout, then draw on the sheet. Use Show through white if the sheet already has a white background. Turn off Show reference to inspect your strokes on their own. Each sheet keeps its own reference in this browser; downloads and saved assets contain only the drawing.

Choose Save asset to upload the current drawing and get a public image URL. Use on page saves the latest version if needed and inserts it in the active page. Choose Copy link when you want to place the drawing in an existing field or use it outside Studio.

Turn on Upload changes automatically when you want Paint to upload revisions after you pause. A changed drawing can receive a new URL. Pages with the prior URL keep showing that version, so apply the new asset when you want them to show the latest artwork.

The Blueprint workspace

Blueprint is the workspace for actions your site takes while someone uses it. The canvas holds nodes and connecting wires. The inspector shows settings for the selected node. Add a node from the picker and search by its label or job. Search for “submit” if you want the event that starts when someone sends a form. Search for “visibility” if you want to show or hide a block.

The node reference lists every available node with its purpose and typed ports. Open it beside Studio when you need the exact name of an input or output.

Move around the graph

Drag with the right mouse button to pan in any direction. Use the wheel to zoom toward the pointer. Fit graph brings everything into view, and Frame centers your selection. Zoom in when you need to work precisely on a port. On touch, drag an empty part of the canvas to pan.

Organize a growing graph

Use Find to locate a node already on the graph. Use Add node when you need a new one. Click the minimap to jump to another area. Collapse Details for more room, or use Focus to give the canvas the screen. Open Details again when you need to edit the selected node.

Box-select related nodes before applying commands to the set. Drag a selected node to move them together. Use Arrange to align the selection, or add a comment around it to name the steps. Give significant nodes a clear title or note in Details. Lock nodes that should stay in place while you arrange their neighbors. Open Graph → Bookmarks to save the current view and jump back to a named area later.

Use the selection commands to copy, duplicate, or delete a group. Copy and paste let you reuse a pattern elsewhere on the canvas. Verify the destination blocks and tables after pasting, especially if the pasted routine is meant for another page. Select a connection to inspect its endpoints, jump to the source or destination, or remove that wire.

A readable graph follows the order of the interaction. Put the event on the left, steps that prepare data in the middle, and the visible result on the right. Place an error branch below its success branch. Use distinct paths for separate visitor actions, even when both update the same block.

Review a graph before editing it

Use Fit graph to establish where the work lives. Select one event and read its target in Details. Use Find to jump to an action by its name, block target or note. Frame the selected group so you can work on it more closely. Use the minimap when the next action falls outside the current view.

Read from the event toward the result. Group the nodes that prepare data separately from the write and the visible outcome. Label groups with what they do, such as “Write the Inbox record and report a failure”. Search the picker by the required behavior and compare the descriptions before placing an action. After adding it, check whether it needs a target block, table or value wire.

Events, wires, and values

An event node is the entry point of a graph. Click starts from a page block, Input change starts when a field changes, Form submission collects the fields of a form, and Page load starts when a page opens. Some events let you select a page or a particular form field. Choose an explicit target whenever the interaction belongs to one page or control.

Execution wires

They determine when things happen. Connect an event's Run output to the first action, then follow its Next, Yes, No, Success, or Error output as appropriate.

Value wires

They carry information such as text, a number, a record, or an array. Connect the output of the node that supplies the value to a compatible input on a later step.

Provide both kinds of wire when an action needs to run and receive input. For example, connecting a form's Fields to a later node gives that node the submitted object. The execution wire tells the later node when to process it. Values produced by an action become available after that action has run on the same branch. A Constant supplies a fixed value without an execution step.

Build one path at a time. First confirm the click or submit event is connected to the intended block. Then connect a visible outcome such as Set text, Change visibility, or Show notification. Use a condition when an interaction has more than one result. Attach feedback to both outcomes where the distinction matters to the visitor.

For repeated routines, create a Flow input, give it a clear name, and finish the routine with Return value. Call it from an event path with Run flow. Use For each item to apply a flow to items in an array. A flow can be tested on a simple example before you call it from several places. Use flow-run variables for values needed during that interaction and page-scoped variables for shared values while a page remains open.

Resolve missing targets and incompatible connections before exporting. Read the node and port labels rather than relying on the wire color alone. If a database or request node exposes both success and error, connect the success branch to confirmation and the error branch to useful feedback. Add Log value at the nearest step where you can check an unexpected input or output.

Control how often a path can run

Put Throttle flow before an operation that should run at most once in an interval. Put Run once per page before an action that should happen once until reload. Both expose Pass and Fail paths, so a skipped action can have its own behavior. Wait pauses a running flow for a configured delay. Timer after delay starts a separate flow once after page load. Timer interval starts a sequence of ticks and lets you limit how many ticks occur.

Blueprint validates graph size and puts limits on work at runtime. A graph supports up to 1,200 nodes and 6,000 wires. An individual run can use up to 8,000 steps within two minutes. HTTP request nodes support timeouts up to 30 seconds. Where bursts of events are expected, keep each path short and use throttling to control repeat calls. Use the Preview Console to see where a path reached a limit or encountered an error.

Trace execution and data separately

In the Inbox demo, follow Run through the mapper and across to the write. Trace the submitted object separately from Fields to Source, then from Result to Field values. Check both paths when an action runs with an empty input. A value supplied by another action is available after its producer has run in that flow.

Test each risky action in both directions. A mapping error and a failed write in the demo go to a separate feedback step, while a successful write goes to confirmation. If the path runs with the wrong value, put Log value right after the producer. Reproduce the same input in Preview, then compare the measured type with the receiving port's type. Try empty strings, missing keys and zero values.

No-code recipes

Use the recipes as patterns. Create the target blocks in Design first, give their content recognizable labels, then add the nodes. Test each flow in Preview before combining it with another interaction.

Reveal details with a button

  1. Add a Button with the label “Show details” and keep its URL at the default #. Add a Text block immediately below it containing the details.
  2. In Logic, add Page load, select the current page, and connect its Run output to Change visibility. Target the Text block and set the mode to Hide.
  3. Add Click and target the Button. Connect Run to a second Change visibility node, target the same Text block, and choose Toggle.
  4. Open Preview. At first, the details should be hidden. Click once to show them and again to hide them. Reload Preview and check the starting state again.

For details that can simply expand and collapse by themselves, try a FAQ block. Use Blueprint when the trigger lives elsewhere or opening the details also changes another block.

Mirror a field into live page text

  1. Add an Input with the label “Display name” and a Text block with the content “Your name appears here.”
  2. Add Input change in Logic and select the Input block. Add Set text and choose the Text block as its target.
  3. Connect the event's Run output to Set text's execution input. Connect its Value output to the Set text value input.
  4. In Preview, type a name and then delete it. To display a fallback for an empty value, put a Condition before the Set text actions and add a branch with your fallback sentence. Test both branches.

If you put a group of inputs inside a Form and target the Form in an input event, check the Form field setting. The event can react to one specific control or to changes anywhere inside the form.

Show a message based on a choice

Add a Select block with the options Product | product and Support | support on separate lines. The first part is visible to the visitor. The second part is the value supplied to the graph. Add an output Text block so both branches have somewhere to write their result.

  1. Target the Select with Input change and add a Condition.
  2. Connect Run to the condition's execution input and Value to the condition's value input. Set its comparison to Equals and enter support as the comparison value.
  3. Use one Set text node for Yes and another for No. Both can target the output Text block with different messages.
  4. Test Product, Support, and the initial empty state. Set a default selection or an opening message if visitors need to see a meaningful result before changing the field.

Save a form submission to a table

To inspect the entire workflow first, choose Open form + database demo from the project menu and open Logic. The mapper in the example connects its form fields to the sample table.

Create a Form with two required controls. Give the name field the internal name name and the email field the internal name email. In Data, create an Inquiries table with required Name and Email fields. Copy the actual field IDs from the Fields tab. Field IDs stay stable when display labels change.

In Logic, add Form submission and target the Form. Add Map object fields. Connect the event's Run output to the mapper's execution input and its Fields output to the mapper's Source input. Select the mapper, open Field map in Details, and use Add field mapping to create these two rows. Replace the examples with the field IDs you copied.

  • Destination key: your Name field ID. Source field path: name.
  • Destination key: your Email field ID. Source field path: email.

Add Create record and choose Inquiries as the target table. Connect the mapper's Success port to Create record's execution input and its Result port to Field values. If you change a form field name, update its matching value in Field map.

Connect Create record's Success and Error ports to separate feedback actions. The success message can say “Your inquiry was received.” The error message can say “Your inquiry could not be saved. Try again.” Try leaving a required field empty to check the browser's form validation.

In the table's API access tab, enable the operation visitors need for the submission. For a contact form, Create records is usually enough. To check the database's Error branch, test a valid submission with Create records off and Enforce public API permissions on. Then enable Create records and test again with Preview open on the updated draft. Use Keep test records when you want a successful Preview submission to appear in your draft.

Validate a quantity and calculate a total

Add an Input labelled “Quantity” with type Number and a Text block for the total. You will use a fixed sample unit price of 25. Start with Input change for the quantity. Connect its value to Convert to number and connect the execution ports.

  1. Connect the converter's Success and numeric Result to Require number range. Set the minimum to 1 and maximum to 50.
  2. Continue through Multiply numbers and pass the validated number into Number A. Enter 25 for Number B.
  3. Pass the result into Format number and then Set text. Connect each preceding Success port and matching Result port so the output is available when Set text runs.
  4. Connect the converter and range check error paths to feedback such as “Enter a quantity from 1 to 50.” Check blank input, 1, 50, and 51 in Preview.

Use Condition or another check when the next step depends on a comparison. Use Require value, Require email, and Require text length for constraints visitors should fix before a later step runs.

Switch an image with a selector

Add an Image block with a working default address and a Select block. Give each option a descriptive label followed by its own direct URL. Use Committed field change and target the Select. Wire its Run to Set image URL, select the Image as the target, and wire Value to URL. When each choice needs different alt text, take the successful path to Set image alternative text and pass a description that corresponds to that choice.

Try both choices on Phone and Desktop. The URL action validates address format. Preview is still needed to see whether the external host serves the file.

Data and API access

In Data, use New table to organize records that share a purpose. Add fields in Fields, including types such as text, email, number, date, boolean, and JSON. Mark a field required when every row needs it. Add a few representative records with Add record to check the structure before importing a large list or wiring up a form.

Use Import CSV after defining the fields. Align column headings with the target fields and start with a small sample. Open the imported rows and check punctuation, dates, empty cells, and numeric values. Use Export CSV when you need a copy of a table's draft records. Exporting a CSV and downloading the entire site ZIP serve different purposes.

Choose the operations a visitor may use

Open API access for the individual table. Every operation starts off. List records returns a collection, Read one record returns a row by its ID, Create records inserts, and update or delete changes stored records. Enabling an operation exposes it to visitors of the exported site. A contact inbox generally needs Create records. A public directory generally needs List records. Give a table only the access its public feature needs.

The exported runtime uses SQLite and applies the table schema and public operation settings. For visitor accounts or access that depends on an individual user's identity, arrange that in the published application's backend. Avoid using a public list operation for an inbox containing private submissions.

Browser requests run in the visitor's browser. Anything configured in a request or included in the public JavaScript can be inspected. For API credentials that must stay private, use a backend endpoint you control. For no-code projects, choose public request endpoints intended for browser use or use the included table runtime.

Define and test the smallest useful schema

Begin with the table's purpose and the minimum fields that support it. For an inbox, Name, Email and Message are enough to test the workflow. Make a field required when the form and mapper both supply it. Copy stable IDs from Fields. Changing a readable label keeps the underlying field ID available to existing mappings.

Backend workflows

Open Backend → Workflows to edit the logic that runs on the server. A workflow starts when the server receives an HTTP request with a matching method and path. Select New to add a route. The first endpoint starts at GET /api/status with a JSON response. Use Send request to see its status, body and execution trace.

Build a request flow

  1. Set a path under /api/ and choose a method. Use :id in a configured path to match a value such as /api/products/123. Enter the real value when testing.
  2. Use Add node and search for the operation you need. Each node lists its fields, expected input and purpose. Use the Details panel to name the node and choose what should run on success or error. Nodes without a manual destination run in order.
  3. Choose From workflow to use request data or a previous node result. A path such as request.body.email picks one field. A result can feed a decision, a database operation, or the final response.
  4. Finish with a JSON or text response and set an appropriate status. For a write endpoint, exercise valid data, a missing field, and a failed write. Use Validate to check branches and references before publishing.

Backend nodes can access the draft's table definitions and data. To insert a row, pick a table, then supply an object keyed by its field IDs. Server-side table actions follow the workflow's route access policy. The separate table API uses the permissions configured in Data.

For a button or form on the website, use Call backend route in Logic. For example, a form can take its Fields output, call a POST endpoint, and display a success message for the returned body. The server route can validate the body, write to SQLite, and return a result. Preview runs requests against temporary draft data. Publish a private release to test persistent writes and registered services.

Use public and private hosting to test a running release against its own database, then share the appropriate address.

Connections, registered programs, and Rust

Use Backend → Connections to register an HTTP address under a short name. Choose the allowed method and configure the connector node with that name. Connectors use a registered destination and send request fields as data. If the destination needs a credential, configure a saved alias for the connection. Use Allow this address on the private network for a service on your own network or VPS.

The registered task node runs a named program from the server configuration and passes its input as JSON. Server clock is available as a simple test. A VPS administrator can register additional labels and fixed argument lists in PLOT_SERVER_TASKS or a JSON file designated by PLOT_SERVER_TASKS_FILE. Each task entry has a label and an argv array starting with the program's absolute path.

Rust operations call the compiled helper on the VPS from the workflow. Choose an operation from the Rust category and configure its inputs in the same Details panel. For a standalone ZIP, set up the bundled helper with the command in BACKEND.md. Store credentials on the server and verify the success and error branches on your private hosted link.

Add a workflow package

Open Backend → Packages. Enable a reviewed package for the current project and expand its action list. In Workflows, open Add node and search by action or package name. Use the Packages category to see all enabled package actions. The editor shows each action’s input fields and describes its output.

  • CSV Toolkit reads header-based CSV into records and writes structured rows back to CSV.

  • Document Text fills named fields in a plain text template and measures the text against size limits.

Try a quote endpoint. Add Convert to minor units and bind its input to the request body. Connect a JSON response to the action’s result. Calculate a quote in decimal values

Create a practice POST route such as /api/practice-quote, then add Calculate quote totals from Decimal Billing. Bind lines from request.body.lines. Set optional taxRate to the sample fraction 0.075 as decimal text and choose 2 decimal places. Start with a JSON response bound to the operation’s result.

{
  "lines": [
    {"quantity": "3", "unitPrice": "19.995"},
    {"quantity": 2, "unitPrice": "4.10"}
  ]
}

The operation rounds each line half up, adds the rounded lines and rounds the tax on that subtotal. Expect line totals 59.99 and 8.20, a subtotal of 68.19, tax of 5.11 and a total of 73.30. The integer totalMinorUnits is 7330. A configured fractional rate of 0.075 means 7.5 percent for this example.

Try zero quantity, an empty list and a fractional number sent without quotes as unitPrice. These inputs are rejected. In a second practice route, send {"amount":"19.995","decimals":2} to Convert to minor units and check for "20.00" and 2000. The action accepts a precision from zero to four places. It calculates from the values you give it. Price selection, applicable tax, creating an order and taking payment are separate operations.

Fill and measure a plain-text document

Add Fill text template from Document Text. Use simple named placeholders such as {{reference}}. Give the action a template string and a fields object. Field values can be text, numbers, booleans or null. The output contains the rendered text and the names actually used.

{

Check and normalise a phone number

Shape collections before you respond

Use Backend list and object actions to keep the output contract small. For a practice route, pass request.body.rows as the list input, then test these operations with a few sample records rather than the full table.

  • Project list fields chooses output names and source paths. Map two nested values to flat response fields. Test a missing path with Missing fields set to null, omit and error to see what each gives the caller.
  • Sort list by field takes an explicit sort type and direction. For a list of numbers, choose number and send numbers rather than numeric text. Equal entries keep their order. Missing and null values sort last.
  • Distinct list by field keeps the first or last occurrence. Index list by text field builds a lookup and lets you pick how duplicate text keys are handled. Use its error policy when a duplicate means the source data needs fixing.
  • Join two lists by key expects unique right-side keys. Compare left mode, which keeps unmatched left rows with a null match, with inner mode. Paginate a list reports the current numbered page, total, page count, and next and previous indicators. Sort before paginating when results need a stable order.

For object inputs, Fill missing fields can fill absent values and optionally nulls. Rename object fields rejects collisions. Flatten object paths keeps arrays intact, and Expand dot paths rejects a key used both as a value and as a parent. These actions shape temporary results. To change stored rows, connect a database write after validation.

Check analytics on a small known sample

Try Summarise numbers on records with a minutes field. Pass the array as the input and minutes as the field path. Use values 12, 6, 18 and null. The summary has count 3, sum 36, mean and median 12, minimum 6 and maximum 18. Missing and null values are skipped.

  • Calculate percentile interpolates between sorted values. The 90th percentile is 16.8 for this sample.
  • Count histogram buckets with boundaries [10,15] puts one value in each bucket. Add 10 to check that a value on a boundary goes to the bucket beginning at that boundary.
  • Sum amounts by group needs a group path and a numeric amount path. Compare the sum and numeric count for two groups. Test a reporting window

Add UTC time window to calculate a reporting boundary from an ISO timestamp. For weekly totals, choose week. The node returns a Monday start and the next Monday in UTC, so timestamps with different offsets can be compared consistently.

Test 2026-05-03T23:30:00-04:00. That instant is Monday in UTC. Expect a start of 2026-05-04T00:00:00.000Z and an end of 2026-05-11T00:00:00.000Z. Use Time in window to include the start and exclude the end. A record at the exact boundary then belongs to just one weekly report.

Use ISO calendar week for a week label and keep the returned week-year with the week number. If a business report follows local midnight, define that requirement explicitly and test the time zone conversion before adopting UTC windows.

Test a timestamped signature

Use a disposable POST route such as /api/receipt-check. Add Verify timestamped HMAC before any write. Bind Raw payload to request.raw, Unix seconds to request.headers.x-sample-timestamp, and Signature to request.headers.x-sample-signature. Select the server key alias PLOT_SECRET_FIXTURE. Have the success path return a small JSON receipt and leave the error path to reject the request.

The signed input is the Unix timestamp in seconds, a literal dot, and the exact body text. Keep spaces, line endings and encoding consistent. Use HMAC-SHA256 with a disposable test key and a hex signature. The node accepts a plain hex digest and the optional sha256= prefix. The default clock tolerance is 300 seconds. Use a fresh timestamp and send the request within the chosen window.

  1. In Request body (JSON), paste the exact text your fixture signer used. For this example use {"report":"sample","total":4}.
  2. Expand Test headers and secrets. Paste a JSON object with x-sample-timestamp and x-sample-signature as strings under Request headers (JSON). Under Temporary secret aliases (JSON), enter {"PLOT_SECRET_FIXTURE":"plot-receipt-fixture-only"} if that is the key used to sign the example.
  3. Use Send request and check that the signature step succeeded. Change the body while keeping the old signature, then try a correctly signed but expired fixture. Both should reject the request. Missing headers and a missing key are separate errors. Use the trace to distinguish the missing value, unavailable key and signature rejection.
Generate disposable test headers locally

Run this with Python 3 on your own machine. It prints the header object for the example above. This is test data for Request test. The project’s verification flow is built with nodes.

import hashlib
import hmac
import json
import time

body = '{"report":"sample","total":4}'
timestamp = str(int(time.time()))
message = (timestamp + "." + body).encode("utf-8")
signature = hmac.new(b"plot-receipt-fixture-only", message, hashlib.sha256).hexdigest()
print(json.dumps({"x-sample-timestamp": timestamp, "x-sample-signature": "sha256=" + signature}))

Require idempotency key checks the key’s format. Your workflow still needs a way to enforce uniqueness and handle concurrent deliveries.

Select History on the project row to see up to 30 recent revisions, with timestamps, notes and the Current marker. Use Download .plot beside any listed version for a protected copy. To recover an earlier version on the server, choose Restore on its row, then Confirm restore. This creates a new current revision and keeps the previous one in history, subject to the revision limit. Use Open current and confirm Replace to load the restored version in the editor.

Package a site ZIP

Use Export for the finished website. A static ZIP contains HTML pages, styles, JavaScript, and packaged local assets when present. It retains remote image addresses. For a site with a table, the ZIP also contains a Python runtime and database schema. The SQLite export dialog gives you the option to include records as seed data. Leave that option off for a clean database or when the draft contains test or private records.

Check the exported files

Extract the ZIP to a new folder. For a static export, serve the files with a static host and make index.html the home page. To check it locally, open a terminal in the extracted folder and run the command below, then visit http://localhost:8080/.

python -m http.server 8080

For an export with Data, start the included runtime from the extracted folder. The bundled DATABASE.md describes the API, permissions, and runtime files. Use the runtime behind HTTPS when deploying a data-backed site.

python runtime.py --port 8080

Follow the primary links and repeat the main interaction in the extracted export. If you use a database, submit a test record, confirm it persists, and check that the allowed operations match your intent. A site can be ready for export even when its production hosting is a separate task.

Guide for AI operators

This workflow is for an assistant using the browser to build in Studio. Treat the user's page requirements, content, and asset list as the scope. Use the editor's normal controls, blocks, styling fields, and built-in nodes. Preserve existing work by checking the current project before creating, importing, or replacing a draft.

  1. Establish the project. Read the active project name and page list. Create a checkpoint if the draft is already in use. Keep a short checklist of intended pages and actions.
  2. Build the page structure. Create page names and slugs, add the navigation, and place sections in reading order. Use realistic copy from the project instructions and wire basic navigation before adding conditional behavior.
  3. Keep inputs stable. Set clear labels and field names. For images, use only approved direct image URLs supplied for the project and verify each one loads. Keep URLs and copy editable in the appropriate Content tab.
  4. Connect interactions. Locate the right page and target block in each node. Keep a record of the event, outputs, and expected behavior for each route. Use the recipes as building patterns.
  5. Test with real controls. Check the main path, smaller devices, typing and tab order where relevant, and the error path of a data action. Use sample data with no private information.
  6. Save and hand off. Save the editable .plot file in the requested location. Export a ZIP when deployment files are requested. In the handoff, list the pages created, interactions verified, and any assets or settings that still need the user.

Useful project instructions specify which project to open, the style, pages, and at least one behavior that can be tested. The example below is ready to adapt.

Build a service studio site in PLOT using the visual editor and built-in nodes. Create Home, Services, and Contact pages. Use the copy and image URLs I supplied. On Contact, save name and email to an Inquiries table and show separate success and failure messages. Check the result in Desktop and Phone Preview, then save a server copy and tell me what passed.

If a step behaves unexpectedly, inspect the visible state before repeating it. Check the form field names, the target block, the menu item's destination, and the latest console messages. Report the concrete gap when a required service, image URL, or project is unavailable. Keep the handoff clear enough that someone else could reproduce the test through the editor.

Leave a reproducible handoff

Give the operator a starting draft, a definition of done and boundaries. For example, “Use a new draft, build Home and Contact, stop after one verified Preview submission, and save an editable checkpoint.” When the work belongs in an existing draft, name it and specify the checkpoint.

Ask for evidence that someone can repeat, such as “Phone Preview opened Contact and the Submit event targets its form.” Check the page and field settings in the UI before changing graphs. Use the draft's actual table and field IDs. Report which changes landed in the draft, which records were temporary, and whether a release was made. Use synthetic addresses and keep credentials out of captures and examples.

Check a workflow before handing it off

Open the actual endpoint in Backend and record its method, path, access rule and expected result. Follow each value from the request or a previous node to its next use. Check which nodes run on success and which run on error. Record any package ID and version the draft needs, then compare them with the Packages panel on the server that will run it.

Use Request test to collect one successful result and one expected rejection. Write down the fixture, HTTP status, relevant trace step and effect on records. If a workflow needs a signed request, use a test alias and a synthetic payload. For a connection to an external service, separate the checks that passed against a fixture from the ones that still need a configured test service.

For a portable handoff, include the editable .plot file and the backend ZIP. Check the ZIP’s requirements and runtime notes, and identify the service settings that must be recreated in the next environment. Use the advanced examples to set up a repeatable check.

Troubleshooting

The graph runs without a visible result.
Check the selected event target, page, and execution wires. Add Log value after the event to verify it fires. Open the action settings and check the target block and value input.
A value is missing or appears on the wrong branch.
Check that the producer runs before the consumer on that route. For an object or array, confirm the property path or item index you are using. Check input type and make conversions explicit.
A request or database operation fails.
Connect the Error branch, look at the Preview Console, and reproduce the smallest failing request. For a record write, verify required fields, field IDs, field types, and table permissions.
A picture loads for you but disappears for a visitor.
Open the direct address in a private browser window. Check HTTPS, link expiration, and whether the host permits displaying the image on other sites.
Phone layout shifts or scrolls sideways.
Inspect the widest child. Check its fixed width, minimum width, long unbroken text, and the column or flex layout of its parent. Retest in Preview at Phone width.
The ZIP opens but the form cannot write records.
If the ZIP includes SQLite, run the included runtime and visit it through its HTTP address. Confirm the table permits the public operation and that the exported schema contains the fields used by the graph.

Background reading for the graph interaction model is available in the Unreal Engine Graph Editor documentation.

Identify the smallest failing step

  1. Record the page, device, input and action that reproduce the problem. Repeat in a fresh Preview.
  2. If a block is missing before interaction, check Design and device overrides. If the interaction never fires, inspect the event target and execution wire. If the output is wrong, compare the produced value and the input's type.
  3. In Backend, compare the actual request method and path with the route definition. Check status and body before changing the response node. In a data-backed export, verify the runtime and table permissions.
  4. Make one correction. Repeat the original failing case, the ordinary case and any affected error branch.

A 404 for a backend workflow points first to the method and path. A message about a required field points to the submitted fields or mapper. Record the first useful symptom before adding nodes or enabling extra permissions.
