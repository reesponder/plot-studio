What the exam covers

Build an editable project for Northline Workshop Operations. Connect the participant site, private records and staff workflows, then verify how the app behaves when requests fail or repeat.

42 tasks in five modules

You get ten hours of active work. The full brief opens when you start. The server grades your submitted project. You need 85 out of 100 and all required checks.

  • Participant site and Blueprint

    Eight tasks on the participant journey, form submission and feedback.

  • Private data and intake

    Nine tasks on typed records, validation and controlled writes.

  • Operator routes

    Eight tasks on protected access, finding records and reporting.

  • Signed decisions and replay

    Ten tasks on trustworthy partner updates and repeated delivery.

  • Verification and recovery

    Seven tasks on request tests, failure cases and the state left behind.

How to prepare

Work through the foundations, then rehearse the same skills in a fresh project before your timed session.

Foundational practice

These four worked drills use the earlier Workshop Requests scenario.

  • Build the intake endpoint

    Validate the seat count and return a minimal response after writing the row.

  • Protect the lookup endpoint

    Test an authenticated request, a denied request and a missing record.

  • Verify the partner callback

    Use the raw request body to verify a signature before updating a row.

  • Connect the browser form

    Wire successful and rejected requests to separate feedback actions.

Rehearse from a blank draft

  1. Create a separate practice project

    Create a private Practice supplies table with a text item and an integer quantity. Add a route that writes only after both values pass validation.

  2. Check three distinct responses

    Test a numeric string, a fractional quantity and a missing field. Compare response status and whether a row was added.

  3. Exercise permissions and replay

    In a disposable rehearsal, test a lookup with and without credentials. Send the same signed callback twice, then inspect the row and its count.

Submission and scoring

Upload one editable .plot file per submission. The exam workspace shows the result and the checks to review before trying again.

What the grader inspects

The grader reads the data schema, browser Blueprint and Backend routes from the editable file. It runs API checks with fictional requests and temporary credentials against an isolated database.

How to use your submissions

You can submit up to three versions while the session is active. If a check fails, compare the response and stored state separately. Leave live keys and customer records out of the upload.

How the certificate works

After passing, issue the certificate and download its PDF in the exam workspace. Enable public verification before sharing the reference ID or verification link.

For hiring teams

Workflow Architect is relevant to roles that own browser inputs, stored data and server decisions. Ask candidates to walk through a request trace, predict a refused request’s effects or explain their replay check. Verify a certificate.
